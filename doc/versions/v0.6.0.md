# v0.6.0 — Sub-Agent System & Major Refinements

> Release date: 2026-06-11

## 新特性：子代理系统 (Sub-Agent System)

实现了一套完整的子代理调度系统，支持 CommanderAgent 将用户任务拆分并委派给专门的子代理执行。

### 架构

```
用户 ──► CommanderAgent (调度层)
              │
              ├─► create_sub_agent(agent_type="planner", ...)
              │       └── Planner: 制定开发/测试计划 (≤25轮)
              │
              ├─► create_sub_agent(agent_type="worker", ...)
              │       └── Worker: 实施计划，产出代码 (≤50轮)
              │
              ├─► create_sub_agent(agent_type="reviewer", ...)
              │       └── Reviewer: 审计产出，输出通过/不通过 (≤15轮)
              │
              └─► create_sub_agent(agent_type="git_helper", ...)
                      └── GitHelper: git add + commit (≤10轮)
```

### 代理定义

| 代理 | 职责 | 迭代上限 | 说明 |
|------|------|---------|------|
| **CommanderAgent** | 用户主入口，意图识别、任务拆分、调度子代理、结果汇总 | N/A | 不直接执行文件操作，只通过 `create_sub_agent` 工具调度 |
| **Planner** | 制定开发计划和测试计划 | 25轮 | 计划持久化到 `.oy-agent-output/plans/{uuid-v7}-简介.md` |
| **Worker** | 执行计划，产出代码/结果 | 50轮 | 生成完整可编译代码 |
| **Reviewer** | 审计代码，输出通过/不通过及改进建议 | 15轮 | 同一子问题最多重试 15 次 |
| **GitHelper** | 整理 git diff，提交 commit | 10轮 | 生成有意义的 commit message |

### 核心文件

- `oy-agent/src/domain/sub_agent.rs` — 子代理类型枚举、System Prompt 模板、迭代上限定义
- `oy-agent/src/infrastructure/agents/commander_agent.rs` — CommanderAgent 实现
- `oy-agent/src/infrastructure/agents/sub_agent_runner.rs` — 子代理有界循环执行器
- `oy-agent/src/infrastructure/tools/sub_agent_tool.rs` — 统一 `create_sub_agent` 元工具

### TUI 集成

- **Shift+Tab** 切换 MainAgent / CommanderAgent
- 状态栏显示当前 active agent：`<MainAgent>` / `<CommanderAgent>`
- 底部 `Sub-Agents` 面板显示子代理执行状态（▶ 运行中 / ✓ 完成 / ✗ 失败）
- 两个 agent 共享 UI 会话历史，各自维护独立的 LLM 上下文
- 各自的 response receiver 合并为统一事件流

### 约束

- 各子代理达到推理轮次上限立即返回错误
- CommanderAgent 不直接调用文件/执行命令，只调度子代理
- 改动最小化、模块解耦，不侵入现有 MainAgent / Reactor / Worker 核心逻辑
