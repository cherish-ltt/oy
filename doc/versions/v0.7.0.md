# v0.7.0 — GrepTool, Clippy Thresholds & Code Decomposition

> Release date: 2026-06-13

## Bug 修复

### 系统提示词注入修复
- **commits** `0404fc9`、`dcef8df`
- **Agent trait 新增 `insert_message_front` 方法**：允许在消息列表最前面插入消息。
- **`assembly_prompts` / `inject_user_message`**：改为检测首条消息的 `role` 是否为 `System`，而非硬编码假设，正确决定系统提示词注入位置。
- **系统提示词插入位置**：改为插入最前面（而非追加到最后），确保 Agent 角色定位始终在首位。
- **`replace_messages_preserve_system_prompt`**：当目标消息列表为空时正确过滤源消息中的 System 角色消息，避免系统提示词丢失。

### CLI session 选择器修复
- **commit** `cc6ea82`
- 提取公用函数，明确区分选择器返回 `Cancel` vs `Invalid`，消除歧义。

### GrepTool Windows 条件编译
- **commit** `eeff459`
- Unix 使用系统 `grep`，Windows 返回提示消息，通过 `#[cfg]` 条件编译隔离平台代码。

## 功能特性

### Tool 超时机制 — 防止工具调用卡死 Agent 循环
- **commits** `c952abc`、`b767976`、`20c8c22`
- **Tool trait 新增 `default_timeout()` 方法**：每个工具可声明自己的默认超时时间（普通工具 150 秒，`create_sub_agent` 为 900 秒/15 分钟）。
- **LLM 可动态覆盖**：每个工具的 schema 新增可选 `timeout` 参数，LLM 可根据任务复杂度自行调整超时限制；未传则走工具默认值。
- **系统提示词更新**：每个工具的 `get_system_prompt()` 已追加默认超时说明，LLM 可据此决策是否需要增加超时。
- **Worker 执行层超时包装**：`spawn_regular_tool_task` 和 `spawn_sub_agent_task` 均用 `tokio::time::timeout` 包裹；同步工具经 `spawn_blocking` 执行以确保超时可真正取消。
- **超时不等于错误**：超时后返回 `[Timeout] Tool execution exceeded N seconds` 信息给 LLM，Agent 可据此决定重试或更换策略。
- **TUI 实时显示**：ToolCallMsg header 从 `(0.5s)` 改为 `(0.5s/150s)` 格式，同时显示已用耗时与超时上限，用户可直观感知剩余时间。

### 新增 GrepTool — 系统 grep 搜索工具
- **commit** `2f289dd`
- 新增 `GrepTool`，通过系统 `grep` 命令搜索文件内容，支持正则表达式、路径过滤、扩展名过滤和结果条数限制。
- **参数**：`pattern`（必填，正则）、`path`（可选，默认当前目录）、`extension`（可选，如 `"rs"`）、`max_results`（可选，默认 50）。
- Unix 平台调用系统 `grep -rn`；Windows 返回提示信息引导用户使用 `findstr` 或 WSL。
- 在 `oy-code-cli` 和 `oy-tui` 的 `register_default_tools` 中注册，含完整单元测试。

### 社区 PR 合入 — 不可读目录跳过
- **commit** `2002b2d`
- `list_sub_agent_sessions` 遇到不可读目录时跳过而非 panic，增强健壮性。
